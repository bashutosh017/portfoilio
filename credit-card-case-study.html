01 / Problem definition

Make a high-stakes workflow more informed.

Credit approval prediction is a useful machine-learning exercise because it turns structured applicant information into an estimate that can support an initial review. In any real lending workflow, a model output should be treated as decision support—not as an automatic approval or rejection. Human review, clear explanations, and appropriate governance remain essential.

02 / Dataset

Data provenance comes first.

The repository README describes 1,000 realistic applicant records and simulated market noise, with an 80.3% rejection / 19.7% approval class split. It lists age, city tier, employment type, monthly income, CIBIL score, and FOIR percentage as model inputs; application ID is excluded to avoid leakage. A dataset citation, license, or downloadable data file is not provided.

03 / Model development

LightGBM, with attention to the pipeline.

The README describes LightGBM with cost-sensitive class-imbalance handling and hyperparameter settings of is_unbalance=True, 100 estimators, max depth 5, and learning rate 0.05. It names model.py as the training engine, but that file is not in the repository root; the deployed Flask app loads serialized model and feature artifacts with joblib.

05 / Deployment

Deployed demo, with a clear boundary.

The project is deployed on Render as a Flask application. Its POST /predict endpoint validates applicant inputs, loads the serialized LightGBM model with joblib, and returns an approval estimate. The current app uses a 0.35 probability threshold; the result is a demo prediction, not a financial decision or production credit assessment.

06 / Limitations

Prediction is not the same as a fair decision.

  • Bias and representativenessHistorical labels and sampling choices can encode unfair patterns. Subgroup analysis and careful governance are necessary before real use.
  • UncertaintyA model score is not a guarantee. Threshold choices change trade-offs between false approvals and false rejections.
  • Data shiftApplicant populations and economic conditions change; model performance can decay without monitoring and periodic review.
  • ScopeThis project is an educational prediction system, not a validated financial product or a substitute for human review.
